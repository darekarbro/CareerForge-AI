# Independent synthetic holdout authoring

This directory's `holdout.json` was authored by a separate holdout-author agent using only the requested schema, public canonical skill vocabulary, and semantic annotation policy supplied in the task. The author did not open or inspect parser, matcher, application implementation, prior fixtures, tests, or results. The author did not run, import, or otherwise execute the application or an evaluation. No example text was sent to the implementation agent during authoring.

The file contains exactly 24 new fictional cases: 12 formatting cases (`fresh-format-01` through `fresh-format-12`) and 12 contradictory-skills cases (`fresh-conflict-01` through `fresh-conflict-12`). Names, organizations, education providers, locations, and work histories are fictional. Email addresses use the reserved `.test` domain. No personal data or consent-dependent source material was used.

Formatting examples vary section names, case, whitespace, separators, contact placement, column-like layouts, sentence wrapping, ASCII framing, and table-like text. Skill punctuation and the supplied aliases are included. The contradiction group contains direct conflicts in both orders, alias conflicts, multiple conflicts, unaffected nearby positives, denial-only evidence, quoted non-candidate statements, quoted instructions, and unrelated-negation controls. Membership in that group does not mean every case contains a semantic contradiction; the controls test that distinction.

Labels follow semantic reading rather than presumed implementation behavior. Explicit positive candidate skill assertions are included in `expectedExtraction.skills`, including skills the job does not ask for. A skill with both a candidate-positive assertion and an explicit candidate denial is withheld from positive extraction and marked `uncertain` when the job requests it. Denial-only evidence is `missing`. Non-candidate quotations, requested approaches, aspirations, and adjacent unrelated negation do not create or cancel candidate skill evidence. Aliases are normalized only according to the supplied mapping. Each case's notes state its annotation rationale. No overall fit score or invented human rating is included.

Only basic structural checks were performed by the author: JSON parsing, schema keys and value types, canonical vocabulary membership, exactly 24 cases with the specified group counts and ID ranges, unique IDs, unique fictional contact identities, and valid requirement category/status values. These checks do not execute the parser, matcher, or evaluation. Semantic labels remain subject to an independent reviewer before first evaluation.

Limitations: this is a small synthetic holdout, not a sample of real applicant documents or a production prevalence estimate. Plain text cannot establish how source PDFs or word-processing files would have been extracted. The cases cover selected language and formatting behaviors and do not establish general accuracy, fairness, multilingual quality, or robustness to every contradiction. An independently authored label can still contain an annotation mistake; review should be performed without changing labels in response to model output. Evaluation results should be reported per group and with their small denominators visible.
